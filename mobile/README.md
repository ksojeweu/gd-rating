# Мобильный рейтинг (WML + CoreBoard mobile)

Отдельная копия системы auto-update для мобильной доски. Основные скрипты и файлы не затрагиваются.
Workflow: `.github/workflows/mobile-auto-update.yml` (запуск каждые 30 минут со сдвигом, либо вручную).

## Что где лежит
| Файл | Что это |
|---|---|
| `scripts/mobile-update.py` | всё одним запуском (его вызывает workflow) |
| `scripts/mobile-levels.py` | уровни мобильной доски -> `levels_mobile.json` |
| `scripts/mobile-rating.py` | рейтинг по WML -> `gdr.txt` (аналог gd-rating.py), ведёт `coreboard_id_map.json` |
| `scripts/compare.py`, `coreboard-parse.py` | копии основных, переключены на мобильные данные и `mobile/world` |
| `scripts/levels.py` | мобильный поиск уровней по названию (без глобала, подменяет общий) |
| `scripts/lists_core.py`, `wml.py`, `list_wml.py` | WML: данные берутся со страниц уровней `/demonlist/1` … `/demonlist/300` (рекорды, «first beaten by», игровой ID уровня); топ игроков и страницы игроков не качаются |
| `levels_mobile.json` | уровни: ключ = название CoreBoard, место, T, t, место и название на WML, игровой ID уровня `gd_id` (сам обновляется) |
| `level_aliases.json` | `{"название на WML": "название на CoreBoard"}` (руками) |
| `coreboard_id_map.json` | ID игроков CoreBoard mobile -> ник и WML-ID (`{"<ID>": {"nick", "gdr_id"}}`), единственный файл с ID игроков: сам ведётся по cbd.txt, ключ = ID игрока на CoreBoard (из ссылок `/player/<ID>`), `gdr_id` пустой, пока на WML нет аккаунта; можно править руками |
| `my_extras.json` | записи, которые есть на CoreBoard, а на WML нет (пересобирается целиком) |
| `cbd/` | что есть у нас, а на CoreBoard нет: missing_achievements*.json, missing_players.json, commands.txt |

## Система ID
- ID CoreBoard пишется в `cbd.txt` в [скобках] в конце строки (как ID WML в `gdr.txt`): `5) 🇵🇱 ник (Уровень, Уровень 88%) - 14.41 [123]`. Берётся с сайта (ссылки на игроков вида `/mobile/board/player/<ID>`), запасной вариант (нет ID на сайте) — `coreboard_id_map.json` по нику. `compare.py` сопоставляет игроков по нему.
- Игрок: ID его аккаунта на WML. Ник на сайте может меняться, ID нет. Если ник на CoreBoard пишется иначе, чем на WML,
  допиши в `coreboard_id_map.json` запись `"любой номер": {"nick": "ник на CoreBoard", "gdr_id": "WML-ID"}`, номера при пересборке расставятся заново.
- Уровень: ID = название уровня на CoreBoard (скобки в названии остаются в ID, но при сравнении не читаются). Алиасы с CoreBoard
  (`Имя = Уровень`) получают ключ `xИмя`. `mobile-levels.py` берёт топ-300 WML (со страниц уровней, вместе с игровым ID уровня), затем список CoreBoard. Пары, которые уже были, остаются по `gd_id` (уровень мог сдвинуться по месту или поменять название; `--rebuild` игнорирует старые пары), остальное сопоставляется построчно:
  на одной позиции то же название -> пара; иначе уровень WML ищется в списке CoreBoard сверху вниз среди свободных; не нашёлся ->
  без ID, в пары не попадает. Всё это пишется в `mobile_levels_report.txt` (уровни WML без ID, уровни CoreBoard без пары, сдвиги).
- Запись на WML находит свой уровень по игровому ID (`gd_id`), поэтому одинаковые названия не путаются; по названию и месту ищется только если ID нет в `levels_mobile.json`.
- Рекорды: со страницы каждого уровня берутся все записи (в том числе прогресс; скрытые «Показать все N» лежат в том же HTML) и «first beaten by» (100% без видео, если игрока нет среди рекордов). В рейтинг попадают только игроки, у которых есть запись на топ-300. Видео берутся из самих записей.
- Страницы уровней кешируются в `scripts/wmlcache.json` на 15 минут (чтобы `mobile-levels.py` и `mobile-rating.py` не качали их дважды); если страница не скачалась, берётся старый кеш этого уровня.

## Первый запуск: что проверить
1. В логе `mobile-levels.py` должно быть число уровней. Если пишет «разобрано 0», разметка `/mobile/levels` отличается:
   пришли кусок HTML вокруг первого уровня.
2. Блок «Сверка с CoreBoard» в логе `mobile-rating.py`: очки должны сходиться с CoreBoard. Если нет, формула мобильной
   доски отличается (проверь T, t и место уровней).
3. `mobile_levels_not_found.txt`: уровни WML без пары. Если это уровень под другим названием, допиши в `level_aliases.json`.
4. Ники из `cbd_not_in_gdr.txt` (в артефакте debug-files) без пары: допиши запись в `coreboard_id_map.json`.
